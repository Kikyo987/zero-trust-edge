## 7. App container privilege escalation fails

**PASS.** Manifest and runtime image require uid 65532, no privilege escalation, and dropped capabilities. A setuid-root helper then fails under PR_SET_NO_NEW_PRIVS, which is what allowPrivilegeEscalation: false sets.

- The control run without NO_NEW_PRIVS becomes root, so the helper really is setuid.
- This is the Linux mechanism the container runtime configures. It is not a trace from a live kubelet exec.
- Distroless has no shell; the behavioral twin is this helper plus the deployment securityContext.

```text
  deployment runAsNonRoot: ok
  deployment runAsUser 65532: ok
  deployment allowPrivilegeEscalation false: ok
  deployment readOnlyRootFilesystem: ok
  deployment drop ALL: ok
  deployment seccomp RuntimeDefault: ok
  runtime image USER 65532:65532: ok
```
